# M1 实施记录

更新：2026-11-06。状态：实施中；尚未通过真实模型发布验收。

## 已查明的兼容性

- 本机：macOS 27.0.1，Apple Silicon / arm64，16 GiB 内存。
- Docker Engine 29.8.2 / Compose 5.5.0，OrbStack linux/arm64 引擎可用。
- 系统 Python 3.9.6 不满足上游要求。独立安装 Python 3.12.16，OpenHands SDK 1.60.1 已成功安装；安装成功尚不等于执行验收通过。
- SDK 1.60.1 的 DockerWorkspace 默认平台是 amd64，RemoteConversation 会把 Agent 与模型配置交给远端。M1 选择可信控制进程中的本地 SDK 会话，通过 SDK 的工具扩展接口调用受限 ARM64 容器，避免把模型密钥交给任务代码。
- SDK 内置费用限制不是每次请求前的预算预留。DooNex 必须在模型请求和工具执行前独立检查停止状态及预算，关闭隐式重试，并保留未知用量。
- 当前常用 API key 环境变量未配置，已请求供应商、实际模型 ID、凭据引用和独立 API 测试预算。未经确认不进行真实模型调用。

## 实施顺序与职责

1. **兼容性与适配**：锁定 SDK/Python/镜像；验证导入、工具扩展、会话持久化、恢复和合成秘密不落盘。只开放受控 shell 工具；SDK 工作目录与用户项目、HOME 分开，禁止项目插件在控制进程执行。
2. **隔离与证据**：明确起始提交，建立独立工作副本；容器只挂载任务代码，不挂载宿主 Git 管理目录、SSH、Docker socket 或控制服务秘密；无网络、非 root、去除 capabilities、只读根文件系统、进程/内存/CPU/时间限制。验证在单独的固定快照副本中进行。
3. **产品闭环**：FastAPI + PostgreSQL 持久化不可变任务输入、运行、事件和动作意图；独立 worker 串行领取任务；React/TypeScript/Vite 工作台显示真实状态、日志、预算、差异和证据。
4. **预算和恢复**：请求前预留调用/token/估计费用；结果未知不退回预留；暂停/取消阻止后续派发；在途动作限时并终止；崩溃后核对容器/文件/动作，显示中断，要求确认未知外部副作用后才恢复。
5. **验收与交付**：先运行离线 SDK/控制流测试与真实容器失败场景，再在授权预算内完成真实模型样例；更新逐项结果、限制和下一步；检查秘密和生成物后提交、推送并核对远端。

架构基线保持 React、FastAPI、PostgreSQL、SDK、独立 Git 工作区和 Docker。开发阶段控制服务运行在宿主机，数据库由 Compose 启动；不把 Docker socket 传入任务容器。M1 默认无任务网络，依赖需预装到审核过的镜像。不会自动推送或部署用户任务产物。
