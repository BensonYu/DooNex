# M3 实施计划与验收记录

更新：2026-11-06。状态：**实施中，尚未完成验收**。用户在 M2 完成后授权按路线持续推进项目；此授权允许进入后续阶段，不把尚未验证的功能记为已完成。

当前已具备私有 Skill 版本库、固定任务集、批次编排、共享预算、分类指标、推荐选用与回滚的代码和工作台入口。**真实的 5 任务 × 3 组 × 3 次、至少 45 个有效尝试尚未开始；M3 发布验收仍全部待完成。** 代码存在、模拟模型响应或合成任务跑通均不能替代这项真实验收。操作接口、导入格式和限制见 [Arena 使用说明](ARENA_USAGE.md)，评测与推荐规则仍以 [竞技规范](SKILL_ARENA.md) 为准。

## 实施顺序

1. **模型配置与用量**：落实 [模型接入计划](MODEL_INTEGRATION.md)。服务端配置档、明确的角色模型选择、冻结历史配置、模型列表及账户用量只读查询；混合包月与按量模型时总费用保持未知，按量小计仍受共享费用预算约束。离线合同、实际界面和受控真实调用分别验证。
2. **Skill 版本**：导入本地完整 Skill 目录，记录来源、许可、适用范围和权限声明，以内容及元数据形成不可变版本；导入不执行脚本。数据库绑定清单，使用前重新校验；使用锁定版本而非活动源目录。SDK 接收明确选中的 Skill，资产仅挂入现有受限容器，不开放宿主命令、自动发现、MCP 或额外工具。
3. **固定任务集**：任务集版本绑定需求、原始代码、模型/工具/镜像/预算、关键任务与阈值。调优与保留评测集分离；隐藏检查器在 Agent 停止后才挂入独立验证容器，不进入模型上下文或可写工作区。
4. **有界私有评测**：手动创建固定批次，基线加 2–3 个候选，交错排列任务与重复；每次独立工作区与会话。批次调用/token/时长及适用费用总账覆盖全部子运行、失败和未知预留，单 Run 仍有自己的上限。取消、中断及恢复不能清零预算或重放未知动作。
5. **证据与推荐**：按任务等权聚合质量，分别展示有效失败、环境故障、取消、辅助运行、耗时及费用。初步推广严格遵守 [竞技规范](SKILL_ARENA.md)，仅生成候选资格；用户查看证据后选用，影响新任务并可回滚。
6. **实际验收与同步**：完成至少 5 个任务 × 基线与 2 个候选 × 每任务 3 次有效重复，共至少 45 个有效尝试。失败也是有效质量结果，环境故障不得伪装为完成；不足则保持未完成或推荐空缺。完整回归、真实容器、界面、元数据与模型调用记录分开保存，提交并核对 GitHub。

## 已实现的纵向流程

1. **导入与审核**：Skills 页面或鉴权 API 导入完整本地目录，导入不执行脚本。内容、文件模式、目录及声明元数据形成版本；数据库绑定原始检查报告摘要，重新导入不能替换旧回执。新版本先为 `pending`，明确批准且完整性有效后才能用于新 Run 或评测。
2. **冻结任务与计划**：Arena 导入包含 5–10 个任务的本地目录；从各任务指定的 Git 对象保存源快照，隐藏检查器另存。创建批次时固定模型配置及配置档版本、任务集、候选、每 Run/批次预算和环境指纹；基线加 2–3 个已批准候选，重复 1–10 次，按任务和重复轮换各组顺序。每个计划位置创建独立 Run、工作区和会话，不并行写同一工作区。
3. **隔离执行与验证**：SDK 只接收显式 Skill 的不透明指令和资源清单，现有受限工具按需只读挂载 `/skills`。执行阶段只向模型提供任务提示及 `visible_checks`；隐藏检查器不挂入执行容器。Agent 停止后，控制器对固定代码快照创建检查副本，只读挂载 `/verifier`，绑定命令、检查器摘要和任务集报告形成证据。
4. **共享预算与停止**：模型请求在同一数据库事务内预留 Run、角色和批次额度；全部组、失败和未知预留累计入账，已知响应再结算。首次启动时钟、暂停期间耗时和未知额度不因恢复清零。批次取消停止后续派发；到限转为 `budget_exceeded`。子运行中断或暂停使批次中断，须核查后明确恢复整个批次，禁止通过单 Run 恢复绕过批次上限。
5. **指标与选用**：读取结果时重新检查证据，显示每任务/每组的分母、缺失重复、失败分类、稳定性、用量和耗时；缺少必要证据不能算通过或满足推广样本数。指标只提出可靠、成本、速度位置的合格候选；用户明确选用后建立推荐记录，新 Run 再明确选择该记录并冻结 Skill 与推荐来源。回滚新增历史记录，重新核对资格，不改写原成绩。

## 当前边界与未验证项

- 当前 Arena 仅评测 `execute` 的执行角色。普通 `execute_review` 仍可使用执行 Skill，但这不构成审查 Skill 的独立竞技；没有任意角色图、并行执行器或后台实验。
- 批次 `state=complete` 表示计划子运行均到终态。`metrics.complete` 还要求所有计划位置有有效证据覆盖且没有取消、辅助或未完成记录；环境故障使对应有效位置缺失。推荐另要求保留集、重复次数、基线资格和质量门槛，三个条件不能互相替代。
- 当前没有环境故障补跑或自动重试端点。保留原始故障和费用，不将失败转成环境故障，不把重新创建的独立批次混算为原批次。缺少有效尝试时原批次保持指标不完整、推荐空缺。
- 恢复时，存在未决 shell 动作或工作区执行摘要不同于已记录检查点会标记 `arena_assisted`，终态归入辅助组。执行摘要覆盖生成缓存路径及空目录名称/模式，交付快照仍过滤生成物，避免人工帮助藏入缓存后被算作自主完成；介入前已经观察到的检查失败和权限违规仍为失败。检测限于受控检查点和工具窗口，不证明能识别所有人工帮助，当前也没有在评测中追加聊天提示的入口。
- 环境故障仅由控制器的 Docker 控制错误或已列明的供应商传输/限流错误识别。普通测试失败、脚本非零退出、认证或模型配置错误不自动豁免；模型自述不能改变分类。显式越界路径探测会记录违规，真正的隔离仍依赖受限容器，不声称提示过滤能识别所有攻击。
- 推荐按任务集及冻结条件指纹区分；选入新 Run 时精确核对完整模型配置、当前推荐和证据。新任务类别仍由用户核对，当前没有自动识别类别并保证跨项目适用性的机制。Skill 审核、模型/控制器/镜像或冻结资料变化可能使新选用失效；历史记录保留。
- 包月成本为 `null`，不产生以 token 数代替货币的成本优胜；未知调用、价格或耗时不能证明最便宜或最快。没有统计显著性保证，也没有综合分冠军。
- 本轮文档核对不读取真实候选或保留评测材料，不运行模型。私有源码、检查器、候选内容和真实运行工件只能保存在授权的私有目录及项目目标仓库，不进入 DooNex 产品 Git。
