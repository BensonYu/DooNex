# M2 实施与验收记录

更新：2026-11-06。状态：**M2 受控验收已完成**。两个独立项目均取得真实执行、只读审查与最终固定快照检查证据。用户在 M1 验收后确认按路线推进 M2；需求以 PRD P10–P12 为准，不将样例结果推广为任意项目或模型的保证。

## 实施计划

1. 多项目：从 M1 单例迁移至稳定项目 ID，保留原项目、运行、事件与工件。界面显式选择项目，创建运行固定项目与起始提交；列表和详情请求核对项目归属，切换时清理过期异步结果。
2. 有限协作：一个顶层 Run 内固定执行者与审查者两个 assignment，顺序执行，不并行写同一工作区，不递归委派、不自动反复修复。仍可显式选择原单执行流程；旧运行保持可读与可恢复。
3. 交接：执行完成后冻结包含原始代码、修改后代码及差异的只读审查上下文，记录基线、快照和完整性摘要。审查者的容器挂载强制只读，不能修改执行成果或验收命令。
4. 预算与恢复：两个角色共享运行总账和首次启动时间，每个动作附角色标识并保留分项用量。角色切换、暂停和恢复均不重置额度；每角色独立会话，未知动作必须核查，不能重放执行者已完成工作。
5. 最终验证：审查结论绑定代码快照并保存结构化问题；审查通过仍须执行固定快照验收。检查失败为失败，检查通过但审查要求修改为待检查。之后代码或交接证据变化使验证失效。
6. 整合与交付：UI 同时展示项目、角色状态、总预算、分项用量、审查结论及检查结果。采纳预检检测目标提交、分支及脏工作区，不自动覆盖。完整测试、真实容器、浏览器与受控模型验证后更新结果、提交并同步 GitHub。

## 范围边界

- 采用现有 SDK、FastAPI、PostgreSQL 与 Docker，不增加调度服务或框架。
- 一个有效 worker 顺序处理运行；两个角色是固定的有界委派，不提供任意角色图或并发执行器。
- 恢复与两个角色共享同一 Run 预算；用户明确创建的新 Run 是新授权，不宣称任意独立任务跨 Run 共享额度。
- M3–M5 不在本轮范围。真实测试起初沿用累计 10 次调用、100,000 token 上限；触达后停止。随后用户明确授权包月测试无需累计上限，脚本通过显式 `--authorize-subscription-campaign` 将授权变更写入私有账本，保留历史限额、已用额度和失败记录。此选项只适用于已确认的 `subscription`，不能用于按量计费。
- 包月 campaign 的累计授权不改变产品单次运行的调用/token/时长约束。本轮新增成功尝试分别设定最多 10 次调用、100,000 token、300 秒，达到上限仍停止；未增加自动重试、模型回退或无限循环。

## 验证版本与记录

最终应用版本为 `d22d226`。其后只更新交付文档；应用代码、镜像或依赖继续变更时须重新验证。

- `.venv/bin/python scripts/test_local.py --tb=short`：**166 passed，3 个上游 warning，69.44 秒，退出码 0**。包含真实 PostgreSQL、Docker、SDK 循环与模拟传输；真实模型另见上表。
- `pnpm --dir apps/web build` 和 Ruff：均退出码 0。模拟浏览器 14 项断言覆盖迟到请求、项目切换、草稿恢复、删除文件审查与未验收差异显示；真实后端浏览器先通过 26 项，再通过 11 项补查（共 143 个 GET、无 POST 或模型调用），核对两项目不同内容摘要、第二项目专属标记、M1 工件、预算停止差异、下载哈希及刷新后的归属。手机采用单视口截图复核，早期长截图的拼接瑕疵保留为失败捕获记录。
- 初次聚焦测试出现 PostgreSQL 启动时序问题（2 passed、19 errors）：原检查误把镜像初始化的临时 Unix socket 当成正式就绪。改为测试实际 TCP 连接后通过回归，失败未计为通过；临时测试数据库密码也从后续诊断输出中脱敏。
- 实际迁移前已备份私有数据库；迁移前后的 3 个 M1 运行数据相同。模型密钥未出现在已扫描的源码、数据库普通记录或私有运行证据中。
- 收尾时一次私有目录权限整理误将原快照文件从 `0644` 改为 `0600`，读取检查正确地使两条成功记录失效；第三条成功记录的文件也受影响。先备份数据库、停止写入，确认字节摘要、大小及原报告封条未变后，仅按数据库绑定的原始清单恢复 37 个文件的精确权限，不重写清单、报告或压缩包。三条成功证据及三份 M2 交接重新通过完整检查，并由另一 Agent 只读复核；两次失效事件、修复审计和显式恢复事件均保留，预算停止状态和全部用量不变。没有放宽验证器或额外调用模型。归档工具只应收紧新归档副本和私有外层目录的权限，不能递归改动已绑定的代码快照。

命令日志、环境、浏览器截图、原始模型运行及迁移备份保存在私有数据目录；产品仓库不包含这些运行材料、网关地址、访问令牌或密钥。

## 当前限制与下一步

- 只实现固定顺序的执行、只读审查和检查；一个有效 worker。没有任意角色编排、递归委派、并行写入或自动修复循环。
- 审查是模型意见，不保证发现所有缺陷。结构化结果无效、问题未解决、交接过期或检查失败都不能标为已验证。
- 沿用 M1 的离线固定 Python 容器及保守文件策略，不支持任务内 Git、symlink、submodule、在线依赖安装或公网部署。
- 新运行保存独立 Git 基线，可在原仓库搬离后继续交付；旧 M1 运行没有该基线副本，按历史兼容路径读取原仓库，不伪造历史快照。
- 当前只有本轮指定模型/接口取得真实成功。多项目属于同一个本地用户的授权空间，不是团队多租户权限系统。
- 按用户提供的 cc-switch 参考做了模型配置与用量查询研究；当前网关的模型列表和用量元数据已作只读验证。见 [模型接入参考与后续计划](MODEL_INTEGRATION.md)，该记录不表示多模型配置界面、角色模型路由或套餐余额面板已经实现。
- 下一步是收集 M2 实际使用反馈，再按 PRD 的独立验收门槛推进 M3；本轮没有实现 Skill 管理、Arena 或后台自动试验。
