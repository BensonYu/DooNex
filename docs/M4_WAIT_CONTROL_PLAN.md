# M4 等待控制的后续实施顺序

更新：2026-11-06（纽约）。本页是实施计划；正式退出条件仍在 [M4 记录](M4_IMPLEMENTATION.md#8-验证与退出条件)。**正常前台等待上界尚未通过**。可选传输子进程已接入产品，1650 项本机整合验证与限制见 [Responses 记录](M4_RESPONSES_TRANSPORT.md)，尚未部署或验证真实网关。

## 已定位的约束

同步 Responses 的阶段超时不覆盖整段调用。异步桥接原型在连接错误下出现额外 POST，并受未取消的同步准备线程影响；这条候选路径不进入产品。当前 worker 的历史维护、批次汇总、SDK 检查点和关闭、容器清理及前台初始化也都占用等待时间。仅延长模型超时不能解决这些问题。

已有文件体积、动作预算与单次数据库等待限制继续保留。新查询只减少返回、反序列化和逐行连接；尚未证明数据库扫描成本、维护容量或完整路径有界。查询规划和必要索引须使用实际合成规模验证，不能拿 `LIMIT 1` 代替这个结论。

## 当前切片：仅隔离 Responses 传输

在锁定 SDK 的同步 `litellm_responses` 调用边界接入一次性子进程，须显式选择 `isolated_direct_v1`。SDK 的 Agent、会话、工具协议、消息转换与产品预算仍留在父 worker；不引入新的队列服务或并发执行者。原私有原型之后补齐了严格协议、启动环境、持久记录、全局阻止和私有恢复入口，实际证据见 [Responses 记录](M4_RESPONSES_TRANSPORT.md)。

实现与后续变更须持续满足以下合同：

1. **单次授权与数据协议**：版本化的严格 JSON 请求、结果和错误；限定字段、层级、字节数、请求身份和一次终态。拒绝 Python 对象、回调和客户端跨进程传递。父进程一次预留、一次结算；失败、损坏 IPC、退出不明均保留未知，不重发。
2. **秘密和网络**：使用固定可信入口、独立于用户项目的工作目录和最小环境。当前请求密钥经匿名管道传递，不进入命令行、日志或临时请求文件；禁止继承数据库连接及其他秘密。明确 TLS、代理、CA、重定向与实际响应体积边界，不能静默改变已有网络配置。
3. **终止与恢复**：期限覆盖启动、子进程传输与 IPC；所有异常路径都执行有限的终止和回收。启动失败、父进程退出、未确认回收与 PID 重用要有明确处理；无法确认安全时停止后续派发并保留可核查证据。子进程退出不证明远端停止或用量结清。
4. **结果与诊断**：按锁定 `ResponsesAPIResponse` 重建，保留 SDK 必需字段与一个经验证的私有成本字段；不搬运任意响应头。传输阶段、真实 HTTP 状态与请求 ID 通过有限且带来源的错误协议传回，不能伪造 HTTP 异常来绕过诊断校验。

这个边界只能称为**传输子进程期限**。父进程的 SDK 准备、序列化、后处理、数据库回调和会话关闭仍在其外，不能由此宣布整个请求或前台等待有界。Chat 路径、流式调用及未验证模型也不能继承该原型结果。

## 整合与验收顺序

未知工具结果后继续派发的问题已修复，查询与事务缩短改动的历史整合回归 **1350 项通过**，证据见 [M4 记录](M4_IMPLEMENTATION.md)。当前传输边界的最终整合回归 1650 项通过，接下来继续处理前台安全检查、有限维护工作、共享剩余期限与文件/会话容量；残留容器和所有权检查不能为了降低等待数字而省略。故障中断与正常安全让出分别记录。预算预留提交到 helper 身份登记之间的硬退出仍可能留下不可由当前恢复入口解除的缺记录阻止，须按 Responses 记录中的独立合同补齐，不能绕过。

延迟验收使用实际 `Worker.run` 和同一单调时钟，覆盖模型、shell、验证及后台准备阶段的到达情况；记录入队提交区间、最后后台动作、结算与检查点、前台初始化和首次准入。必须同时检查提交后无新增后台派发、无重放、预算与未知保留、容器已终止。正常依赖条件、队列前置任务、容量与超限故障出口需明确并实际验证，之后才能给出数值上界。

真实完整后台矩阵是另一项验收；继续遵守已冻结日预算和原失败记录，不能用离线测试或传输原型代替。研究工件位于本机私有 `verification/m4-wait-bound-design/`、`verification/m4-wait-bound-audit/`、`verification/m4-request-helper-design/`。这些研究没有调用真实模型或访问生产数据库。

## 后续切片的具体边界（尚未整合验收）

1. **预留与 helper 身份原子绑定**：在派发事务外真实核验永久 lease inode，在原预算事务内同时保存 action 和严格初始身份；后续凭确切初始摘要登记，持久确认后才启动。新记录即使在首次登记前硬退出，也须有足够证据供现有严格人工核查；旧缺记录不能补造身份，未知预算不能释放。状态和索引谓词的变化须有显式迁移，不能只修改同名 `IF NOT EXISTS` 定义。
2. **有限数据库维护**：用匹配索引的精确候选查询处理仍预留的后台 allocation 和启用授权，保留现有安全核查及恢复顺序。已结算历史不应继续触发逐项锁定。当前实际探针中，100 个已结算历史在一次 `Scheduler.maintain` 中仍触发 702 条语句、300 次行锁；这是一次性数据库下的样本，不是延迟上界。现有 worker 每轮调用维护两次，实施须计算真实累计工作量，并保持 `claimed_at` 到实际结算时间的保守记账口径。
3. **剩余完整路径**：核对文件、会话与检查点容量、容器清理及前台初始化，再以同一时间线测量实际 `Worker.run`。初始化 DDL 位于 worker 全局执行锁之前，新增索引可能等待已有事务；冷启动与已就绪 worker 的正常等待须分别定义，不能通过忽略初始化或安全核查来得到较短数字。

上述两份只读设计与 PostgreSQL 探针位于私有 `verification/m4-helper-reservation-design-01/`、`verification/m4-database-maintenance-review/`。原子绑定与有限维护已在独立工作区实施中，尚未整合验收；设计报告不代表对应产品能力已通过验证。
