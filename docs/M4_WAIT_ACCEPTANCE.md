## 在最终整合检查前冻结的操作目标

本机受控正常样本的操作目标是 **90 秒以内**：前台入队事务提交至首次实际模型／工具准入提交，按同一宿主 monotonic 时钟测量。提交前后分别记 `before`、`after`，首次准入为 `admission`；区间为 `[admission - after, admission - before]`，以较大的后者核对目标。执行状态事件、`Worker.execute` 入口和供应商收到请求都不能替代实际准入提交。

90 秒是本轮在最终检查前冻结、现已按末尾同源码配对核验的受控操作目标，不是产品新增超时、通用服务 SLA，也不是将请求、清理、准备等局部 timeout 相加得出的保证。不会因样本超出而事后提高目标；超时、外部 watchdog 触发、结果未知和未执行均不算正常通过。每项正常配置至少核对一次专项及一次最终整合的完整观测，并绑定各自实际源码。

适用条件是当前 Apple Silicon Mac mini、固定 Python/SDK/依赖、本机正常响应的 PostgreSQL、Docker daemon、文件系统与已存在镜像；单个有效 worker，无排在目标前面的前台任务。供应商为本地合成响应，无真实模型调用。恢复原 Run 的调用、token、首次启动时钟、父批次／分配／日账和未知预留保持；不为测量修改产品配置或清除阻止状态。

“新 Worker 启动”包含真实 `initialize`、锁、reconcile 和调度核查，但仍使用已启动的宿主、数据库、Docker 和文件缓存；不冒充重启机器后的冷机结果。文件系统永久失联、宿主暂停、无法恢复的数据库／Docker 故障没有按时成功承诺；应保留未知并拒绝新派发。
