## 当前实现与检查

`community.py` 已接入现有 API 与 PostgreSQL 初始化。社区默认关闭，管理、投稿和访客路由分开；投稿及使用凭据只保存摘要，首次显示后不可再读。维护者明确读取固定公开 GitHub 来源，预览完整白名单字段及许可后独立审核、发布。发布不写私有 Library、不创建 Run；下载只提供固定归档，下架停止新准入，既有回执保留。未知来源操作保持待核查，不自动重放。

有限容量按 UTC 日期和累计值持久记录。投稿凭据至多 30 日，每凭据至多 20 份投稿；每份分发最多准入 3 次下载，使用凭据有效 7 日且至多 3 次自报。分发请求和自报失败保留，均不表示安装或控制器核验通过；费用、收益与支付未启用。

## 1. 产品闭环与范围

站点维护者配置社区资料与投稿权限 → 作者提交一个公开 GitHub Skill 定位 → 维护者执行有限发现、查看固定版本及许可 → 单独审核社区发布内容 → 创建不可变发布快照 → 访客查看目录、来源、许可和适用条件 → 下载确切版本 → 在私有 Library 中导入并单独批准使用 → 记录可追溯但不冒充质量证明的分发/使用事实。

私人 Library 的批准不等于公共发布批准。社区发布必须引用明确的公共来源、固定 commit、内容清单、许可及维护者确认；不能将任意私有 Skill、项目、Run、工件目录或原始评测记录挂到公开路由。下架停止新分发，保留私有审核历史和既有版本回执，不篡改已发生下载或执行记录。

| 本次产品实现 | 明确边界 |
| --- | --- |
| 单站点公开目录与版本详情 | 沿用现有技术栈；本机验收不等于已公开部署；社区功能默认关闭 |
| 有限投稿与审核 | 先支持维护者发放的可撤销投稿凭据，普通访客只能读已发布内容；作者名称和声明不能冒充已验证身份 |
| 公开来源的固定版本分发 | 复用 M4 公开 GitHub reader、不可变内容和许可核验；不接受任意 URL、私人目录、远程脚本执行或自动更新 |
| 条件榜单与证据来源 | 按任务类别、模型、环境、预算和样本条件区分；自报结果与控制器核验结果分开；没有合格证据时榜单可为空 |
| 分发与使用归因 | 固定版本、事件来源、时间、去重和撤回状态可追溯；下载请求不等于成功使用、质量或应付收益 |
| 商业规则入口 | 显示尚未启用收费/结算；不预填利润比例、不连接支付、不记假收入或假支付成功 |

本次不建设多租户 SaaS、团队空间、任意托管用户任务或实际支付。后续如决定这些能力，需要独立的账户/项目隔离、服务凭据与发布验收，不由单站点社区顺带开启。

## 2. 架构与权限决定

当前应用的管理 API 仅允许本机 Bearer 访问，直接开放现有 API 会暴露私有工作台。M5 将新增窄范围的社区路由与公开数据投影；管理、投稿和公开读取分别鉴权。公开读取只能查询专门的已发布记录和对应公开内容，不能访问 Library、项目、模型设置、账户余额、Run、原始任务集或工件接口。

继续使用 React、FastAPI、PostgreSQL 和私有内容存储，不引入新的网关、消息队列、身份平台或任意代码插件。默认本机运行；对外地址、受信 Host/Origin、TLS、反向代理和真实部署配置在上线方案中单独核对，不能为演示而把全部 Host 放开。

投稿凭据与工作台管理令牌相互独立，数据库只保存凭据摘要，权限限定于投稿及本人记录；创建时一次性显示，支持撤销与有效期。作者身份首先标明为自报，不根据 GitHub URL、昵称、星数或提交者填写的字段推定所有权。维护者审核的是本次固定来源、许可和声明，而不是承诺作者身份普遍可信。

发布内容单独冻结为白名单字段和文件集合，并保存审核人、内容摘要、来源、许可、发布时间及替代/下架关系。公开响应不通过删几个字段来复用整个私有记录。恶意 HTML、Markdown、链接和文件名以数据处理；浏览器不执行上游脚本或加载上游外部资源。公开下载只能按发布 ID/文件清单取固定内容，不能接受宿主路径。

投稿输入只接受专用公开 reader 可解析的定位；发布输入只能引用社区审核回执，不能直接接收私有 Library version、Run、工件 ID 或路径。公共证据使用独立严格 schema 和逐字段预览，不调用 `Arena.detail` 后减字段形成公开响应。这些边界必须通过 API 合同与 sentinel 测试验证。

## 3. 评测与榜单

[Skill Arena 规范](SKILL_ARENA.md) 继续定义质量口径，不新增一个混合模型、类别与版本的综合分。公开成绩至少标明发布版本、任务类别、模型 ID、环境/预算指纹、样本数量、失败/取消/环境故障、未知用量、验证时间和证据来源。

维护者明确选择要发布的汇总并预览全部公开字段后，才生成公共证据快照。仅允许与已发布 Skill 的确切内容身份匹配、完整性可核查的记录；隐藏任务输入、答案、检查器、项目路径、提示、日志、网关地址、凭据和账户数据永不进入该投影。必要字段无法安全公开或证据过期时，只显示无核验成绩，不能填零或宣称通过。

自报成绩必须显著标明来源且不进入控制器核验榜单。控制器核验也只证明所列条件下的结果，不是跨平台独立认证。候选没有达到原有重复试验和质量门槛时，不因进入社区而取得推荐资格；没有可比记录时保留空榜。版本或模型变化不继承旧成绩，来源变更形成新记录。

## 4. 分发、归因与商业边界

每个下载请求绑定一个不可变发布版本及分发回执。HTTP 请求被接受只能记作分发请求；不能据此宣称文件已完整安装、执行或产生收益。客户端提交的使用报告作为自报事件，不能直接计入经验证使用。受本站控制器核验的使用须绑定实际 Run、固定 Skill 及事件身份，并用唯一约束防止重复计数。

分别保留分发请求、自报使用、本站核验使用以及成功验收次数。失败、取消、重试、重复请求和下架前记录不删除；统计窗口和计数口径可见。公开统计只包含允许的聚合字段，不公开访客网络信息、用户项目身份或 Run 内容。有限速、容量和过期规则，不能通过任意匿名写事件无限增长数据库。

分发与归因的容量和限速须持久保存；事件唯一约束不替代总量上限。下架提交后拒绝新分发准入，已经准入的在途响应单列保留，不能声称可以收回已传输字节。

这些记录不是反作弊已经解决的声明，也不是财务账本。收费、作者分成、税务、退款和支付供应商尚未确定；产品中继续显示未启用，不用模拟资金记录代替真实支付验收。

## 5. 实施顺序与验收

1. 完成 M4 的固定公开来源导入，稳定来源、许可、对象身份与审核边界。
2. 新增社区默认关闭设置、私有管理入口、投稿凭据和有限投稿回执；先验证权限与数据隔离。
3. 完成明确发布、公开只读目录、固定版本分发、下架及原 Library 单独导入审核的纵向流程。
4. 增加白名单评测汇总和条件榜单，验证无合格数据时空缺、来源标注、版本与环境失效。
5. 增加分发/使用归因与去重、审计、统计口径；保持收费未启用。
6. 对最终整合源码运行数据库、Docker、静态检查、前端构建及真实浏览器验收；公开源读取与真实模型任务分别保留证据。

| 验收项 | 最低实际结果 |
| --- | --- |
| 权限隔离 | 未授权访客只能读取已发布数据；投稿凭据不能读工作台、代替维护者发布、修改别人投稿或触发模型 |
| 发布与下架 | pending/rejected/被篡改/许可未知内容不可发布；并发重复发布幂等；下架后零新分发且历史完整 |
| 不可变分发 | 固定 commit、文件 mode/字节/摘要和许可正文相符；原仓库变化不改变已发布内容；下载路径不能逃逸 |
| 私有数据隔离 | 用秘密、项目、隐藏答案和日志 sentinel 检查所有公开响应、下载和浏览器网络请求；泄漏为 0 |
| 评测可信边界 | 自报成绩不进入核验榜；不完整、失败、过期及跨模型证据不继承；同条件可复算且允许空缺/并列 |
| 归因不虚构 | 同一事件多次提交不增加计数；分发、自报和核验使用分开；没有支付时金额/收益不显示已发生 |
| 真实流程 | 本机真实 HTTP/浏览器完成投稿、审核、发布、下载复算、私有导入、下架及权限拒绝；期间不执行上游脚本 |
| 运行证据 | 绑定最终源码、命令、退出码、配置和日志；合成记录只作测试，不能显示为真实外部作者或客户 |

## 6. 发布前仍需维护者决定

DooNex 自有内容的许可证、外部贡献政策、公开站点定位和实际收费规则仍未确定。实现完成可在本机验收；公开上线与收费必须在提供具体页面、公开数据清单、部署目标及操作方案后再确认。用户已授权的 GitHub 代码同步继续按现有仓库规则进行，不擅自修改可见性或选择项目许可证。

实现状态以本页开头的检查记录为准，以下尚无证据的退出条件仍待验证。发现共享存储、权限或许可证处理需要改变既有架构时，先记录具体冲突与最小改动，再更新 [PRD](PRD.md)、[架构](ARCHITECTURE.md) 和 [路线图](ROADMAP.md)。
